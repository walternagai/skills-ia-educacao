\begin{objetivos}
\begin{itemize}
  \item Instalar o OpenCode no seu sistema operacional (Windows, Linux ou macOS) pelo m{\'e}todo mais adequado ao seu perfil;
  \item Conectar o OpenCode a um provedor de modelos e selecionar um modelo dispon{\'i}vel;
  \item Sincronizar as 62 skills e os 6 subagentes do acervo com o ambiente local e conferir a instala{\c c}{\~a}o;
  \item Aplicar, opcionalmente, o controle de vers{\~a}o com Git para proteger seus materiais did{\'a}ticos (passo a passo no Ap{\^e}ndice~\ref{ap:git}).
\end{itemize}
\end{objetivos}

\begin{dicaopencode}
\textbf{Caminho recomendado na primeira instala{\c c}{\~a}o (cerca de 20 minutos)}: Linux, macOS ou Windows com WSL2/Git Bash use o M{\'e}todo~1 (cURL), depois \texttt{/connect} e \path{./install-skills.sh --opencode}; no Windows nativo (CMD ou PowerShell) use o M{\'e}todo~4 (Scoop ou Chocolatey) e \path{.\install-skills.bat --opencode}. Ignore os demais m{\'e}todos por enquanto. \textbf{Pronto quando}: \texttt{opencode -{}-version} exibe a vers{\~a}o, a contagem de skills confere (ver Se{\c c}{\~a}o Confer{\^e}ncia) e o relat{\'o}rio \texttt{info-skills} lista as skills e os seis subagentes. O controle de vers{\~a}o com Git {\'e} opcional, est{\'a} no Ap{\^e}ndice~\ref{ap:git} e pode ficar para depois.
\end{dicaopencode}

\begin{conceitochave}
\textbf{Vocabul{\'a}rio de instala{\c c}{\~a}o (apenas o que aparece neste cap{\'i}tulo)}: voc{\^e} n{\~a}o precisa dominar nenhum destes termos -- basta copiar e colar os comandos indicados:
\begin{itemize}
  \item \textbf{Terminal}: a ``tela de comandos'' do computador, onde se digita texto em vez de clicar. No Windows, {\'e} o PowerShell; no Linux e macOS, o Terminal;
  \item \textbf{Comando}: uma linha de texto que voc{\^e} digita (ou cola) e confirma com Enter, como se fosse uma instru{\c c}{\~a}o por escrito;
  \item \textbf{Terminal do OpenCode (TUI)}: ao digitar \texttt{opencode}, abre-se uma interface com menus dentro do pr{\'o}prio terminal;
  \item \textbf{Reposit{\'o}rio}: a pasta do projeto com todos os arquivos do acervo, baixada do GitHub (como uma pasta compactada, com hist{\'o}rico);
  \item \textbf{Script}: um arquivo de comandos prontos (\texttt{install-skills.sh} ou \texttt{install-skills.bat}) que voc{\^e} executa sem digitar cada comando individualmente;
  \item \textbf{Termos avan{\c c}ados que aparecem e podem ser ignorados}: \emph{PATH} (lista de pastas que o sistema consulta para achar programas), \emph{WSL2} (Linux rodando dentro do Windows), \emph{npm}, \emph{Scoop}, \emph{Chocolatey} e \emph{Homebrew} (gerenciadores de pacotes alternativos) e \emph{cURL} (ferramenta de download usada pelo instalador). O caminho recomendado usa apenas um desses recursos, e o restante deste cap{\'i}tulo explica cada op{\c c}{\~a}o quando for necess{\'a}ria.
\end{itemize}
\end{conceitochave}

\section{Vis{\~a}o Geral do OpenCode}

O \textbf{OpenCode} (\url{https://opencode.ai}) {\'e} um agente aut{\^o}nomo de terminal e assistente de desenvolvimento de c{\'o}digo aberto concebido para operar diretamente sobre o sistema de arquivos local \cite{opencode2026doc}. Trata-se de projeto de c{\'o}digo aberto (licen{\c c}a MIT) mantido pela empresa \textbf{Anomaly} (\url{https://anoma.ly}); por adotar padr{\~o}es abertos como as \emph{Agent Skills} (propostos pela Anthropic) e o protocolo MCP, integra-se a um ecossistema mais amplo de ferramentas -- ver a se{\c c}{\~a}o de autoria no Cap{\'i}tulo~\ref{cap:skills-opencode}. Ao contr{\'a}rio de plataformas propriet{\'a}rias fechadas, o OpenCode oferece:

\begin{itemize}
  \item Total flexibilidade na escolha de provedores de modelos de linguagem (OpenAI, Anthropic, Google, Groq, DeepSeek ou modelos de c{\'o}digo aberto rodando localmente via Ollama);
  \item Interface interativa de terminal rica em recursos visuais (\emph{Terminal User Interface} -- TUI), al{\'e}m de suporte a execu{\c c}{\~a}o em lote (\emph{headless}, ou seja: com uma {\'u}nica linha de comando, sem abrir a interface);
  \item Suporte nativo a ferramentas de inspe{\c c}{\~a}o de arquivos (\texttt{read}, \texttt{glob}, \texttt{grep}), edi{\c c}{\~a}o segura (\texttt{edit}, \texttt{write}), execu{\c c}{\~a}o de comandos de terminal (\texttt{bash}), extens{\~o}es via \emph{Model Context Protocol} (MCP) e gerenciamento de \emph{skills} modulares.
\end{itemize}

\subsection{Detalhamento por Sistema Operacional}

\begin{itemize}
  \item \textbf{Windows}: H{\'a} duas trilhas equivalentes. A primeira, recomendada para desempenho total, {\'e} a utiliza{\c c}{\~a}o do \textbf{WSL2} (\emph{Windows Subsystem for Linux}), que fornece um ambiente Linux nativo dentro do Windows e permite seguir integralmente as instru{\c c}{\~o}es da se{\c c}{\~a}o de Linux. A segunda {\'e} a instala{\c c}{\~a}o \textbf{nativa no PowerShell} por meio dos gerenciadores Scoop ou Chocolatey (ver M{\'e}todo 4). Para a interface gr{\'a}fica, o navegador padr{\~a}o (Edge ou Chrome) abre a interface web normalmente;
  \item \textbf{Linux}: Qualquer distribui{\c c}{\~a}o contempor{\^a}nea com arquitetura x86\_64 ou ARM64 (Ubuntu 20.04+, Debian 11+, Fedora, Arch Linux, etc.); o script de instala{\c c}{\~a}o detecta automaticamente a arquitetura;
  \item \textbf{macOS}: Vers{\~a}o 12 (Monterey) ou superior, tanto em processadores Apple Silicon (M1/M2/M3/M4) quanto Intel; o script oficial produz bin{\'a}rios nativos para ambas as arquiteturas.
\end{itemize}

Ferramentas utilit{\'a}rias b{\'a}sicas no terminal: \texttt{curl}, \texttt{git} e uma conex{\~a}o ativa com a internet para baixa dos bin{\'a}rios e comunica{\c c}{\~a}o com as APIs.

\section{Passo a Passo de Instala{\c c}{\~a}o}

O OpenCode disponibiliza m{\'u}ltiplos m{\'e}todos de instala{\c c}{\~a}o oficiais, equivalentes entre si. O usu{\'a}rio pode optar pelo que melhor se adeque ao seu sistema operacional e ao seu ambiente de trabalho.

\subsection{M{\'e}todo 1: Script Autom{\'a}tico via cURL (Linux, macOS e Windows via WSL2)}

O m{\'e}todo mais r{\'a}pido e direto consiste em executar o script oficial de instala{\c c}{\~a}o no terminal:

\begin{lstlisting}[language=bash, caption={Instala{\c c}{\~a}o r{\'a}pida via cURL}]
curl -fsSL https://opencode.ai/install | bash
\end{lstlisting}

O script detecta o sistema operacional e a arquitetura do processador, baixa o bin{\'a}rio est{\'a}tico otimizado, instala o execut{\'a}vel no diret{\'o}rio \texttt{\~{}/.opencode/bin/opencode} e adiciona essa localiza{\c c}{\~a}o ao arquivo de configura{\c c}{\~a}o do \emph{shell} (\texttt{\~{}/.bashrc}, \texttt{\~{}/.zshrc} ou \texttt{\~{}/.profile}).

Ap{\'o}s a conclus{\~a}o, recarregue as vari{\'a}veis de ambiente do terminal:
\begin{lstlisting}[language=bash, caption={Recarga do shell (Linux/macOS/WSL2)}]
source ~/.bashrc   # bash
source ~/.zshrc    # zsh (padrao no macOS)
\end{lstlisting}

Este m{\'e}todo {\'e} igualmente v{\'a}lido no Windows quando executado dentro do ambiente WSL2 (aberto com o comando \texttt{wsl} no PowerShell ou pelo menu Iniciar).

\subsection{M{\'e}todo 2: Gerenciadores de Pacotes JavaScript (Node.js / npm)}

Funciona nos tr{\^e}s sistemas operacionais. Caso o ambiente j{\'a} conte com o Node.js (vers{\~a}o 18 ou superior) configurado, o OpenCode pode ser instalado globalmente via \texttt{npm}, \texttt{pnpm}, \texttt{bun} ou \texttt{yarn}:

\begin{lstlisting}[language=bash, caption={Instala{\c c}{\~a}o global via npm, pnpm, bun ou yarn}]
# Via npm
npm install -g opencode-ai

# Ou via pnpm
pnpm add -g opencode-ai

# Ou via bun
bun add -g opencode-ai

# Ou via yarn
yarn global add opencode-ai
\end{lstlisting}

No \textbf{Windows}, os mesmos comandos s{\~a}o executados no \textbf{PowerShell} (com o Node.js instalado a partir de \url{https://nodejs.org}); no \textbf{macOS} e \textbf{Linux}, no terminal padr{\~a}o.

\subsection{M{\'e}todo 3: Homebrew (macOS e Linux)}

Usu{\'a}rios dos sistemas com Unix dispon{\'i}vel (macOS e Linux) que j{\'a} adotam o gerenciador \textbf{Homebrew} podem instalar com um {\'u}nico comando:

\begin{lstlisting}[language=bash, caption={Instala{\c c}{\~a}o via Homebrew}]
brew install opencode
\end{lstlisting}

A documenta{\c c}{\~a}o oficial recomenda o tap do projeto, atualizado com mais frequ{\^e}ncia: \texttt{brew install anomalyco/tap/opencode}. A f{\'o}rmula oficial do Homebrew (\texttt{brew install opencode}) {\'e} mantida pela equipe do Homebrew e recebe atualiza{\c c}{\~o}es com menos frequ{\^e}ncia.

Esse m{\'e}todo {\'e} particularmente c{\^o}modo no macOS, pois o Homebrew {\'e} o gerenciador de pacotes mais difundido nesse sistema.

\subsection{M{\'e}todo 4: Windows Nativo (Scoop ou Chocolatey)}

Para instala{\c c}{\~a}o direta no Windows, sem depender do WSL2, abra o \textbf{PowerShell como Administrador} e utilize um dos dois gerenciadores de pacotes:

\begin{lstlisting}[language=bash, caption={Instala{\c c}{\~a}o no Windows via Scoop ou Chocolatey}]
# Via Scoop
scoop install opencode

# Ou via Chocolatey
choco install opencode
\end{lstlisting}

\begin{dicaopencode}
\textbf{Windows: qual trilha escolher?} Se a m{\'a}quina do docente j{\'a} utiliza o WSL2 para outras atividades acad{\^e}micas ou de pesquisa, a trilha Linux (M{\'e}todo 1 ou 2) {\'e} a mais fluida. Para quem prefere permanecer exclusivamente no ambiente gráfico do Windows, a instala{\c c}{\~a}o nativa via Scoop ou Chocolatey atende igualmente ao mesmo conjunto de skills e comandos. A {\'u}nica diferen{\c c}a relevante {\'e} o caminho de armazenamento das skills (ver se{\c c}{\~a}o de sincroniza{\c c}{\~a}o).
\end{dicaopencode}

\subsection{Verifica{\c c}{\~a}o da Instala{\c c}{\~a}o}

Para confirmar se o execut{\'a}vel est{\'a} operando corretamente, consulte a vers{\~a}o no terminal:

\begin{lstlisting}[language=bash]
opencode --version
\end{lstlisting}
A sa{\'i}da dever{\'a} exibir o n{\'u}mero da vers{\~a}o instalada (por exemplo, \texttt{1.18.30}).

\section{Configura{\c c}{\~a}o de Provedores e Modelos de IA}

Na vers{\~a}o atual do OpenCode, a configura{\c c}{\~a}o inicial de credenciais ocorre dentro da interface interativa. Inicie o programa e use o comando \texttt{/connect}; depois, use \texttt{/models} para conferir e selecionar os modelos dispon{\'i}veis:

\begin{lstlisting}[language=bash, caption={Configurando um provedor na interface do OpenCode}]
opencode

# Dentro da TUI:
/connect
/models
\end{lstlisting}

O fluxo de autentica{\c c}{\~a}o varia conforme o provedor: alguns abrem uma p{\'a}gina de login, outros solicitam uma chave de API. Nunca cole uma chave em um arquivo versionado, em um prompt ou em um material entregue aos estudantes. Para verificar os provedores e modelos dispon{\'i}veis, consulte o menu exibido pelo pr{\'o}prio OpenCode, pois o cat{\'a}logo muda com o tempo:
\begin{itemize}
  \item \textbf{Anthropic}: Chave da API Claude; a disponibilidade de modelos e o fluxo de autentica{\c c}{\~a}o devem ser conferidos no menu \texttt{/connect};
  \item \textbf{OpenAI}: Chave da API OpenAI (\texttt{sk-...}) para a fam{\'i}lia GPT-4o e modelos da s{\'e}rie \emph{o1};
  \item \textbf{Google Gemini}: Chave do Google AI Studio para acesso ao Gemini 2.0 Flash e Gemini 1.5 Pro;
  \item \textbf{Modelos Locais (Ollama)}: Para institui{\c c}{\~o}es com pol{\'i}ticas restritas de privacidade de dados que n{\~a}o admitem tr{\'a}fego de dados discentes para nuvens comerciais, {\'e} poss{\'i}vel conectar o OpenCode a inst{\^a}ncias locais do Ollama (\url{http://localhost:11434}).
\end{itemize}

\section{Instala{\c c}{\~a}o e Sincroniza{\c c}{\~a}o das Skills no OpenCode}

Para que as 62 skills do reposit{\'o}rio fiquem dispon{\'i}veis no seu ambiente local do OpenCode, as pastas de skills precisam residir no diret{\'o}rio de extens{\~o}es do usu{\'a}rio, cuja localiza{\c c}{\~a}o varia conforme o sistema operacional:

\begin{center}
  \footnotesize
  \begin{tabularx}{\linewidth}{p{3.2cm}X}
    \toprule
    \textbf{Sistema} & \textbf{Localiza{\c c}{\~a}o das Skills} \\
    \midrule
    Linux e macOS/WSL2 & \path{~/.config/opencode/skills/<slug>/SKILL.md} \\
    \addlinespace
    Windows nativo & \path{C:\Users\<usuario>\.config\opencode\skills\<slug>\SKILL.md} \\
    \bottomrule
  \end{tabularx}
\end{center}

O reposit{\'o}rio prov{\^e} um script de instala{\c c}{\~a}o automatizado que realiza a c{\'o}pia e organiza{\c c}{\~a}o de forma segura. Como o script \texttt{install-skills.sh} {\'e} um script \emph{bash}, ele deve ser executado em um ambiente Unix: terminal Linux, macOS, WSL2 ou \textbf{Git Bash} no Windows nativo. Para quem prefere permanecer no ambiente nativo do Windows, o reposit{\'o}rio prov{\^e} o equivalente em batch, \texttt{install-skills.bat}, execut{\'a}vel diretamente no CMD e no PowerShell (ver \emph{Trilha alternativa: Windows nativo} ao final desta se{\c c}{\~a}o).

\subsection{Obtendo o Reposit{\'o}rio (GitHub)}

Antes de executar o script, {\'e} necess{\'a}rio obter o reposit{\'o}rio \texttt{skills-ia-educacao} no seu computador. Ele est{\'a} hospedado publicamente no GitHub em \url{https://github.com/walternagai/skills-ia-educacao}. H{\'a} dois caminhos equivalentes:

\subsubsection{Op{\c c}{\~a}o A -- Clonar com Git (recomendada)}

A clonagem cria uma c{\'o}pia local que pode ser atualizada com um {\'u}nico comando sempre que o acervo crescer:

\begin{lstlisting}[language=bash, caption={Clonando o reposit{\'o}rio do projeto AvalIA}]
git clone https://github.com/walternagai/skills-ia-educacao.git
cd skills-ia-educacao
\end{lstlisting}

\begin{dicaopencode}
\textbf{Windows}: execute o comando acima no \textbf{Git Bash} (instalado junto com o Git -- ver Ap{\^e}ndice~\ref{ap:git}) ou use o \texttt{install-skills.bat} no PowerShell (ver trilha alternativa abaixo). \textbf{Linux/macOS/WSL2}: no terminal padr{\~a}o. Para atualizar o acervo depois, basta executar \texttt{git pull} dentro da pasta e rodar o \texttt{install-skills.sh} (ou \texttt{install-skills.bat}) novamente.
\end{dicaopencode}

\subsubsection{Op{\c c}{\~a}o B -- Baixar o ZIP (sem Git)}

Para docentes que preferem n{\~a}o instalar o Git: acesse \url{https://github.com/walternagai/skills-ia-educacao} no navegador, clique no bot{\~a}o verde \textbf{Code} e escolha \textbf{Download ZIP}. Extraia o arquivo baixado em uma pasta de sua prefer{\^e}ncia; a pasta extra{\'i}da ser{\'a} a raiz do reposit{\'o}rio para os comandos seguintes. A desvantagem {\'e} que atualiza{\c c}{\~o}es futuras do acervo exigem repetir o download manual.

\subsection{Executando a Instala{\c c}{\~a}o}

Na raiz do reposit{\'o}rio \texttt{skills-ia-educacao}, execute:

\begin{lstlisting}[language=bash, caption={Instala{\c c}{\~a}o automatizada das skills e subagentes no OpenCode}]
# 1. Simular a instalacao para inspecionar os caminhos de destino (dry-run)
./install-skills.sh --opencode --dry-run

# 2. Efetivar a instalacao das 62 skills e dos 6 subagentes
./install-skills.sh --opencode
\end{lstlisting}

O script detecta a pasta pessoal (\texttt{\$HOME}) do usu{\'a}rio e aplica o caminho correto do sistema operacional em uso. Com o destino \texttt{-{}-opencode}, ele copia tanto as skills quanto os seis subagentes do acervo.

\subsubsection{Trilha alternativa: Windows nativo (CMD ou PowerShell)}

Quem instalou o OpenCode pela trilha nativa (M{\'e}todo 4) pode dispensar o Git Bash para a sincroniza{\c c}{\~a}o das skills e subagentes: o reposit{\'o}rio prov{\^e} o script equivalente em batch, \texttt{install-skills.bat}, execut{\'a}vel diretamente no CMD ou no PowerShell. As flags s{\~a}o as mesmas do script bash:

\begin{lstlisting}[language=bash, caption={Instala{\c c}{\~a}o automatizada das skills e subagentes no Windows (CMD ou PowerShell)}]
# 1. Simular a instalacao para inspecionar os caminhos de destino (dry-run)
.\install-skills.bat --opencode --dry-run

# 2. Efetivar a instalacao das 62 skills e dos 6 subagentes
.\install-skills.bat --opencode

# Instalar em todos os CLIs reconhecidos (inclui subagentes no destino opencode)
.\install-skills.bat --all
\end{lstlisting}

O script detecta a pasta pessoal do usu{\'a}rio (\texttt{\%USERPROFILE\%}) e aplica o caminho correto. Sem flags, exibe o uso; com destinos expl{\'i}citos, instala mesmo sem o CLI correspondente no \texttt{PATH}, avisando o docente. Quando o CLI alvo n{\~a}o {\'e} encontrado e o \texttt{winget} est{\'a} dispon{\'i}vel, o script oferece instalar o CLI automaticamente (ex.: \texttt{winget install -e --id sst.opencode}); sem \texttt{winget}, sugere o comando \texttt{npm} equivalente. A remo{\c c}{\~a}o do acervo tem o par correspondente \texttt{uninstall-skills.bat}, com as mesmas flags.

\subsection{Confer{\^e}ncia da Instala{\c c}{\~a}o}

Para certificar-se de que todas as skills foram copiadas com sucesso:

\begin{lstlisting}[language=bash, caption={Verificando as skills instaladas (Bash: Linux, macOS e WSL2)}]
ls ~/.config/opencode/skills/ | grep ia-educacao | wc -l
\end{lstlisting}

No \textbf{Windows nativo} (PowerShell), o mesmo cheque pode ser feito com:

\begin{lstlisting}[language=bash, caption={Verificando as skills instaladas (PowerShell)}]
(Get-ChildItem "$env:USERPROFILE\.config\opencode\skills" | Where-Object Name -like "ia-educacao-*").Count
(Test-Path "$env:USERPROFILE\.config\opencode\skills\aias-consultant")
\end{lstlisting}

O retorno dever{\'a} apontar 61 skills com o prefixo institucional (mais a skill especial \texttt{aias-consultant}, totalizando 62 unidades). Para conferir os subagentes, o script de relat{\'o}rio \texttt{info-skills} (apresentado a seguir) indica se os seis arquivos est{\~a}o presentes em \path{~/.config/opencode/agents/}.

O reposit{\'o}rio prov{\^e} esse relat{\'o}rio pelo script \texttt{info-skills}, que resume o estado da instala{\c c}{\~a}o em todos os CLIs de uma vez (skills completo/parcial/nada por destino e os seis subagentes do OpenCode), dispensando os comandos manuais:

\begin{lstlisting}[language=bash, caption={Estado da instala{\c c}{\~a}o via script de relat{\'o}rio (Bash e Windows nativo)}]
# Linux, macOS e WSL2 (ou Git Bash no Windows)
./info-skills.sh --all --verbose

# Windows nativo (CMD ou PowerShell)
.\info-skills.bat --all --verbose
\end{lstlisting}

Antes da instala{\c c}{\~a}o, o par \texttt{doctor-skills.sh}/\texttt{doctor-skills.bat} averigua os pr{\'e}-requisitos do computador (bash, curl, git, node 18 ou superior, npm e os CLIs alvo); a flag \texttt{-{}-fix} instala os CLIs ausentes via \texttt{npm} quando poss{\'i}vel (ex.: \texttt{./doctor-skills.sh --all -{}-fix}).

\subsection{Disponibilizando os Subagentes}

A partir da vers{\~a}o v0.10.8, os scripts \texttt{install-skills.sh} e \texttt{install-skills.bat} copiam automaticamente os seis subagentes quando o destino \texttt{opencode} {\'e} selecionado (\texttt{-{}-opencode}/\texttt{-{}-all}) -- o mesmo comando da se{\c c}{\~a}o anterior, sem passo adicional. Nos demais destinos (\texttt{-{}-claude}, \texttt{-{}-codex}, \texttt{-{}-antigravity}, \texttt{-{}-antigravity-cli}, \texttt{-{}-gemini}) os subagentes n{\~a}o s{\~a}o copiados, pois s{\~a}o configura{\c c}{\~o}es espec{\'i}ficas do OpenCode.

Se o OpenCode for executado em uma pasta separada da c{\'o}pia do reposit{\'o}rio, ou se voc{\^e} preferir copiar os arquivos manualmente, a opera{\c c}{\~a}o equivalente {\'e} (a partir da raiz do reposit{\'o}rio):

\begin{lstlisting}[language=bash, caption={C{\'o}pia manual dos subagentes (Linux, macOS, WSL2 ou Git Bash)}]
mkdir -p ~/.config/opencode/agents
cp .opencode/agents/*.md ~/.config/opencode/agents/
\end{lstlisting}

No PowerShell, a opera{\c c}{\~a}o equivalente {\'e}:

\begin{lstlisting}[language=bash, caption={C{\'o}pia manual dos subagentes (Windows PowerShell)}]
New-Item -ItemType Directory -Force "$env:USERPROFILE\.config\opencode\agents"
Copy-Item ".opencode\agents\*.md" "$env:USERPROFILE\.config\opencode\agents\"
\end{lstlisting}

Execute os comandos a partir da raiz clonada do reposit{\'o}rio. Depois de atualizar o acervo com \texttt{git pull}, repita a instala{\c c}{\~a}o e reinicie o OpenCode. Os arquivos dos agentes n{\~a}o fixam um provedor: eles usam o modelo selecionado pelo agente principal.

\section{Primeiros Comandos no OpenCode}

\subsection{Iniciando a Interface Interativa (TUI)}

Basta digitar o comando no terminal dentro do diret{\'o}rio do seu projeto acad{\^e}mico ou disciplina:

\begin{lstlisting}[language=bash]
opencode
\end{lstlisting}

Uma interface limpa e intuitiva ser{\'a} renderizada no terminal, permitindo enviar mensagens, aprovar a{\c c}{\~o}es de leitura/escrita e selecionar o modelo desejado em tempo real. Dentro da interface, as skills s{\~a}o invocadas por meio da barra inicial: por exemplo, digite \texttt{/ia-educacao-rubrica} ou \texttt{/aias-consultant} e pressione Enter para acionar a skill desejada.

\subsection{Execu{\c c}{\~a}o Direta de Comandos (\emph{Headless Mode})}

Para instru{\c c}{\~o}es r{\'a}pidas ou integra{\c c}{\~a}o com scripts do docente, utilize o subcomando \texttt{run} mencionando a skill pelo slug (a barra pode ser omitida em modo headless, pois o texto do \emph{prompt} j{\'a} identifica o identificador):

\begin{lstlisting}[language=bash, caption={Exemplo de execu{\c c}{\~a}o direta com skill}]
opencode run "Utilize a skill ia-educacao-rubrica para estruturar uma rubrica analitica para uma apresentacao oral de estagio com nivel AIAS 1."
\end{lstlisting}

\subsection{Atualiza{\c c}{\~a}o do OpenCode}

Para manter o OpenCode sempre na {\'u}ltima vers{\~a}o est{\'a}vel:
\begin{lstlisting}[language=bash]
opencode upgrade
\end{lstlisting}

\section{Problemas Comuns na Primeira Execu{\c c}{\~a}o}

\begin{itemize}
  \item \textbf{O comando \texttt{/connect} n{\~a}o aparece}: confirme que o programa foi iniciado com \texttt{opencode}, e n{\~a}o com \texttt{opencode run}; em seguida, atualize o OpenCode com \texttt{opencode upgrade}.
  \item \textbf{A skill n{\~a}o aparece}: confirme o caminho de instala{\c c}{\~a}o, feche e abra o OpenCode novamente e verifique a contagem apresentada na subse{\c c}{\~a}o de confer{\^e}ncia.
  \item \textbf{O subagente n{\~a}o aparece no menu \texttt{@}}: copie os arquivos de \texttt{.opencode/agents/} para \texttt{~/.config/opencode/agents/}, conforme a subse{\c c}{\~a}o anterior, e reinicie a aplica{\c c}{\~a}o.
  \item \textbf{O script n{\~a}o executa no Windows}: use Git Bash ou WSL2 e execute-o na raiz extra{\'i}da ou clonada do reposit{\'o}rio; o PowerShell n{\~a}o interpreta scripts Bash diretamente.
  \item \textbf{O modelo gratuito n{\~a}o est{\'a} dispon{\'i}vel}: abra \texttt{/models} e escolha outro modelo. Disponibilidade, limites e nomes podem mudar sem altera{\c c}{\~a}o deste manual.
\end{itemize}
